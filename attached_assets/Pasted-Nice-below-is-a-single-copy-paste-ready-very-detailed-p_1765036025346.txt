# Replit prompt — create a working prototype of **Scheme-Easy / Benefit-Bridge**

**Project name:** `scheme-easy` (alias `benefit-bridge`)

**Goal:** Build a working prototype (web + mobile-friendly) of a multilingual, voice-first chatbot app that maps a spoken user situation to government welfare schemes (scholarships, subsidies, loans) using a Retrieval-Augmented-Generation (RAG) pipeline.

**High-level requirements**

1. User speaks (or types) in their native language.
2. Speech → Speech-to-Text (Whisper/OpenAI or local fallback).
3. System embeds the transcribed text and uses a vector store to find the most relevant scheme PDFs/chunks.
4. LLM synthesizes a crisp, simple reply listing exactly which schemes the user qualifies for and the documents they need — in the user’s language, simple words, and with step-by-step next actions.
5. UI is minimal but friendly: record voice, show transcription, show retrieved schemes and final suggestion, allow TTS playback.
6. System must be runnable locally in Replit with sample content (20 sample scheme PDFs or placeholder text files) so demo works without external crawling.

**Tech stack (explicit)**

* Backend: Python (FastAPI).
* Vector store: FAISS (local) via LangChain (or local Chroma if user prefers). Default: **FAISS**.
* Embeddings & LLM: OpenAI API (or compatible model). Use embeddings API for vectorization and GPT for generation. (Make provider configurable.)
* STT: OpenAI Whisper HTTP API (if key available). Provide a fallback that uses a lightweight offline STT placeholder (or simulated transcription) for the demo.
* Frontend: Flutter Web (preferred) OR a simple React web UI if Flutter web is problematic in Replit. *Default implement both lightweight options and run React to be certain it works in Replit; include Flutter web skeleton as README step the developer can run locally if they want.*
* Optional: TTS: use browser TTS (SpeechSynthesis) for web; provide Flutter TTS plugin usage notes.
* Data ingestion: Python script that converts 20–30 PDF files (or sample TXT files) into chunks, cleans text, generates embeddings, and saves FAISS index + metadata (SQLite or JSON). Provide a sample `sample_data/` with 6 real short synthetic example PDFs (or text files) describing typical schemes (crop insurance, small farmer grant, pension scheme, student scholarship, housing subsidy, small business loan). The ingestion script should run automatically on first start in Replit.

## Backend: behavior & endpoints

**app.py (FastAPI)** — endpoints:

1. `GET /health`

   * returns status + whether models/index loaded.

2. `POST /ingest`

   * starts ingestion: reads `sample_data/` PDFs/txts, extracts text, chunking (500-1000 chars with 100 overlap), generates embeddings, builds FAISS index, stores metadata JSON (title, doc_id, original filename, chunk_start, chunk_text, scheme_meta fields like eligibility bullet points if present).
   * Should run on startup automatically if index not present.

3. `POST /transcribe`

   * Accepts multipart form audio file (wav/mp3/ogg).
   * If `WHISPER_API=true` call OpenAI speech-to-text API; else run demo fallback (simulate OR use local whisper via whisper.cpp if installed).
   * Returns: `{ "transcript": "...", "language": "auto-detected" }`.

4. `POST /query`

   * Body: `{ "text": "...", "top_k": 5, "language": "auto" }`
   * Steps:
     a. Embed query.
     b. Retrieve top_k chunks from FAISS (return metadata).
     c. Build a prompt using a fixed template (below) and include retrieved chunks.
     d. Call LLM completion API with system prompt + user prompt; set temperature low (0.0-0.2) for reliable precise output.
     e. Return structured JSON:

```json
{
  "answer": "final human-friendly text in user language (or both)",
  "schemes": [
    {
      "title": "Crop Relief Grant",
      "confidence": 0.87,
      "extracted_requirements": ["Farmer ID/land records", "Damage certificate", "Mobile number"],
      "source_file": "gov_crop_relieff_2024.pdf",
      "source_excerpt": "..."
    }
  ],
  "raw_retrieved": [ ... ],
  "llm_tokens": { "prompt_tokens": 0, "completion_tokens": 0 }
}
```

5. `POST /ask-audio`

   * Accepts audio file, calls `/transcribe`, then `/query`, return combined result.

6. `GET /metadata`

   * Returns list of loaded schemes and brief metadata.

**Important backend details**

* Use LangChain’s text splitter and vectorstore wrappers if possible; otherwise implement simple chunking + FAISS.
* FAISS index saved to `backend/models/faiss_index.pkl` (and associated metadata JSON).
* Metadata must include eligibility criteria and "plain-language" paraphrase of document requirements (ingest step should attempt to extract bullet lists; if not possible, flag for manual curation).
* Add a short fallback pipeline: for small data sets, if FAISS unavailable, do simple keyword match.

## RAG prompt templates (exact copy to include in `rag.py`)

**System prompt (instruction to the LLM):**

```
You are Scheme-Easy assistant. Task: given a user's situation and a set of retrieved document excerpts describing government welfare schemes, produce:

1) A short direct answer (1-3 lines) stating exactly which schemes the user appears to qualify for. Use confident but cautious language (e.g., "You *may* qualify for...") when uncertain.

2) For each suggested scheme, list the **exact documents** required in simple words (no legal jargon), and where the user can obtain them if applicable, and any likely next steps (e.g., "Visit Gram Panchayat office", "Apply online at example.gov.in").

3) A one-line "why this fits" explanation (which criteria from the retrieved text matched the user's situation).

4) All text should be simple, suitable for low-literacy users. Keep sentences short. Use the user's language; if not specified use English. If you detect a different language in the input, reply in that language.

5) Output in strict JSON format with fields: "summary", "schemes": [ { "title", "why", "documents":[...], "next_steps": [...], "source_file", "confidence" } ], and "follow_up_questions" (list of at most 3 clarifying questions). Do not include any other fields.
```

**User prompt (append the retrieved chunks):**

```
User situation:
"{user_text}"

Retrieved documents (each labeled with source filename and excerpt). Use ONLY the information in these excerpts to decide relevant schemes:

[ DOC 1: source_file_name.pdf ]
"excerpt text..."

[ DOC 2: ... ]
"excerpt text..."

...etc.

Now produce the JSON described above. If information is missing to decide eligibility, ask 1–3 follow-up questions in the follow_up_questions array.
```

**Note:** enforce JSON-safety by instructing the LLM to only return JSON; the backend should parse with `json.loads` and fallback to a second prompt if parsing fails.

## Ingest script specifics (`ingest.py`)

* Walk `sample_data/` for `.pdf` or `.txt`.
* For `.pdf` use `pdfplumber` or `PyPDF2` to extract text.
* Preprocess: remove headers/footers heuristically, normalize whitespace, split into chunks of 800 characters with 120 overlap.
* For each chunk, produce embedding via OpenAI embeddings API (or local embedding fallback).
* Save chunk metadata: `doc_id`, `file_name`, `chunk_id`, `chunk_text`, `page_number` (if available), `scheme_title_candidate` (first header line or filename), and `eligibility_bullets` (attempt to extract lines that look like bullet lists or contain keywords like "eligib", "eligible", "who can apply", "required documents", "documents required"). Use regex heuristics for extraction.
* Build FAISS index and store `metadata.json` mapping index id → metadata.

## Edge cases & helpful behavior

* **Confidence scoring:** compute simple confidence by retrieval similarity average and LLM temperature. Return 0.0–1.0.
* **Privacy:** do not log full transcripts to public logs; store only in memory for demo. In README highlight privacy risks and advise disabling logs in production.
* **Multilingual:** pipeline: transcribe (native language) → (optionally) translate to English for retrieval if embeddings are English-preferred OR use multilingual embeddings so retrieval works in place. Use model `text-embedding-3-large` (multilingual) or instruct to use `openai` embeddings which are multilingual. For final answer use LLM for translation + simplification into the user language.
* **Failure modes:** if no retrieval match above threshold, respond: "We couldn't find a clear match — please answer 1-2 quick questions" (include those in `follow_up_questions`).
